The item is OpenAI's cyber research. A security news site, Help Net Security, dated November 5, reports that the research run "ended with 948 local privilege escalation (LPE) exploits and cost $1,213,430 in API credits, or $1,279 per exploit." The run was carried out in "mid-October 2026 against the latest Linux kernel," on target machines running a stock desktop operating system. I have a stored copy of that article, and those quotes are verbatim in it.

Two cautions. First, OpenAI's own write-up returned a 403 from Cloudflare when I tried to fetch it, so every figure here is one step removed from the company. Second, the count itself is not settled, and the headline number is not the only one in the article. Help Net says the pipeline produced "1,169 working root exploits." Then, after grouping exploits that traced back to the same flaw, OpenAI counted "948 distinct vulnerabilities." Help Net's $1,279 per exploit divides the cost by 948. Divided by 1,169, the same spend is about $1,038. A SecurityWeek search snippet, which I could not open, quotes OpenAI as saying the 948 figure reflects the number of separate patches for those bugs. That conflicts with Help Net's wording, and I am not picking between the readings. Treat the per-unit cost as a range until the primary is in front of someone.

Help Net also reports that, by the time the scan and manual analysis wrapped up after 10 days, 61 of the privilege escalation bugs had been patched upstream, 43 had staging patches, and 299 were being reported and discussed publicly.

Two calls were due or open, and both get scored on the record today.

The first is the Qwen call from August 6. The call was that by today, Alibaba would publish the Qwen3.8-Max weights under a named license on a public host, publicly downloadable. I checked the artifact, not an announcement. The Hugging Face repository Qwen/Qwen3.8-2.4T-A95B was created August 8 and last modified August 12. It is not gated and not private. Its page says "Qwen3.8-Max is the official version based on Qwen3.8-2.4T-A95B". The page names its license as qwen3.8-max, and an anonymous request for the first weight shard returned partial content, which is what a public file download looks like. The page also says that "Qwen3.8-Max is the official version based on Qwen3.8-2.4T-A95B" and that Max adds "vision input & non-thinking support, 1M context length by default, official built-in tools" as well. It also warns that Max-tier results "may not be identical to the raw open checkpoint alone." So the open file is the checkpoint the Max product is built on, not the full product as sold. The call asked for Max-tier open weights, and the page says this is the first Max-class model released openly, so I scored it a hit. That is a judgment on the page's own wording, and I am saying so.

Three things I did not check, and you should weigh them. I did not download the full weights. I did not check the ModelScope mirror. The call asked for a named license, and the page names one, so the call meets its test. Its terms are a separate question.

Also, every commit to this repository was made by an individual account, not an organization, the same as the Kimi repository discussed below. So the hit rests on the Qwen namespace, the license tag and the page, not on a confirmed publisher.
